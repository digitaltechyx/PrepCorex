Lexi AI Assistant — Phase 1 Plan

PrepCorex / PSF StockFlow · Admin-first, then Client · Due target: 15 Nov
Goal: Lexi can run admin work by chat; client Lexi reuses the same engine with own-account scope.
How admin unlocks client: Almost every write Lexi does (create inbound, approve outbound, restock, invoice, etc.) is the same server action. Admin Phase 1 builds and hardens those actions + Confirm + audit. Client-side Lexi is mainly a second chat mode that calls the same tools limited to the signed-in client’s account — not a full rebuild. So finishing admin first makes client Lexi much faster; it does not appear by magic, but most of the hard work is already done.

1. Suggested sequence (your board order)

  1. Admin Gap audit
  2. Admin Access & safety
  3. Admin Inbound
  4. Admin Outbound
  5. Admin Inventory
  6. Admin Users & pricing
  7. Admin Returns & labels
  8. Admin Outbound invoicing (+ storage draft if included)
  9. Admin Lookups & reports
  10. Client Client-side Lexi
  11. Both QA Testing

2. What Lexi can already do (admin chat)

  • Find clients / products; list pending (one client or all); warehouses; reports/CSV
  • Inbound: create, approve, reject, complete receive, fulfill-all
  • Outbound: create, approve, reject, pick & pack, ship from inventory, dispatch, fulfill-all
  • Restock; return / dispose / delete / quarantine approve-reject; label refund / top-up / API fee review

Still missing on admin Lexi today (examples): invoices/CRM/storage from chat, users/pricing writes, warehouse allocate/move, batches, cancel, buy labels purchase, integrations connect, client chat mode.

3. Task-by-task plan

1. Gap audit
Admin · Foundation
  • List every Admin dashboard action vs current Lexi tools
  • Mark: Done / Partial / Missing / Out of scope for Phase 1
  • Deliverable: short gap matrix (inbound, outbound, inventory, billing, users, labels, reports)
  • Locks the rest of Phase 1 scope so we don’t rebuild finished tools
2. Access & safety
Admin · Foundation
  • Keep Confirm-before-write for every new propose_* action
  • Enforce admin / sub-admin managed-client rules on all new tools
  • Audit log: who confirmed what, for which client, success/fail
  • High-risk actions (wipe, pricing change, invoice send): extra clear summary before Confirm
  • Prep allow-list design so Client mode can later reuse tools safely
3. Inbound
Admin · Ops
  • Close gaps: inbound batches, cancel pending with reason, line/qty corrections, remarks
  • Harden approve / complete / fulfill-all against real Notifications cases
  • Read tools: pending receive vs pending approval clearly separated
  • Reuse later Same create/cancel/complete APIs power Client Lexi inbound
4. Outbound
Admin · Ops
  • Close gaps: batches, cancel pending, tracking number, admin remarks, multi-line edge cases
  • Harden pick & pack / ship from inventory / dispatch / fulfill-all
  • Align with Continue fulfillment statuses (confirmed → ready → dispatched)
  • Reuse later Create/cancel/status tools reused for Client Lexi outbound
5. Inventory
Admin · Ops
  • Beyond restock: qty adjust, transfer between warehouses/bins (where admin UI allows), quarantine actions
  • Stronger inventory lookup (SKU, FEFO, reserved vs sellable)
  • Clear “cannot do from chat” only for true Warehouse Ops floor scans if still excluded
  • Reuse later Client sees own inventory via same read/adjust rules scoped to uid
6. Users & pricing
Admin · Config
  • Find/create/update client profile fields Lexi is allowed to change
  • Assign pricing profile; assign warehouses / features flags
  • Approve/reject user where that is an admin action today
  • Read pricing summary for a client (no silent $0 outbound)
  • Admin-only — not exposed to Client Lexi writes
7. Returns & labels
Admin · Ops
  • Finish return / dispose / delete / quarantine review edge cases (batches if needed)
  • Label refund / top-up / API fee: solid propose + execute
  • Admin buy-labels / purchased-labels lookup (and wallet actions admin already has in UI)
  • Reuse later Client can create return requests / request top-up using scoped tools
8. Outbound invoicing
Admin · Billing
  • On clients: propose Create Invoice (before or after dispatch) from Lexi
  • Off clients: propose Add services → CRM draft from Lexi
  • List invoice / CRM draft status for a shipment or client
  • Recommended add-on in same task: CRM Storage draft generate / status / send sync
  • Admin-only billing writes; clients only get read of their invoices later
9. Lookups & reports
Admin · Read
  • Expand lookup topics: CRM draft status, storage drafts, label wallet, inbound/outbound trackers
  • Richer reports filters; keep generate_report Confirm-free (read-only)
  • Ensure answers use live tools — never guess pending counts
  • Reuse later Client mode gets the same reads filtered to own uid
10. Client-side Lexi
Client · After admin
  • New chat entry on client dashboard (not admin floating chat)
  • Tool allow-list: only own-account create/cancel/view — no other clients, no users/pricing, no admin invoice generate
  • Wire to admin-built actions: inbound/outbound/returns/dispose, inventory read, own invoices/shipped
  • Same Confirm UX; audit tagged as client actor
  • This task is thin if admin tasks 3–9 are complete — mostly UI + scoping + prompts
11. QA Testing
Both · Close Phase 1
  • Admin matrix: approve/reject/fulfill/invoice/pricing for On and Off clients
  • Sub-admin: only managed clients
  • Client matrix: can act on self; blocked from other clients and admin tools
  • Regression: existing Lexi propose_* still work; Confirm + audit entries present
  • Sign-off checklist before calling Phase 1 done

4. What “admin first ⇒ client easier” means

Built in Admin tasks What Client Lexi reuses
Inbound / Outbound / Inventory / Returns actions Same APIs with clientUserId = signed-in user only
Access & safety + audit Same Confirm flow; stricter allow-list
Lookups & reports Same reads, filtered to own data
Users & pricing / admin invoicing writes Not given to clients (admin-only)
Client-side Lexi task Chat UI + prompt + allow-list — not re-implementing ops

5. Suggested message to stakeholder

We are building Lexi admin-first so every important PrepCorex admin action can be done safely from chat (with Confirm). When admin coverage is solid, client Lexi is enabled as a restricted mode on the same engine — clients only act on their own account. Phase 1 board order: Gap audit → Access & safety → Inbound → Outbound → Inventory → Users & pricing → Returns & labels → Outbound invoicing → Lookups & reports → Client-side Lexi → QA.
