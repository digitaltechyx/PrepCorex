1. Purpose

This Addendum supplements Schedule D and describes operational security controls for PrepCorex production systems, company endpoints, and seller integration data (including TikTok Shop tokens and order data). It is intended as verifiable evidence for marketplace partner security reviews.

2. Scope

  • PrepCorex production applications and APIs
  • Cloud hosting and data stores used by PrepCorex
  • Company-managed endpoints used to administer production systems
  • Seller integration credentials and synchronized marketplace order/inventory data

3. Security baseline for daily operations

ControlImplementation
Password complexityStrong unique passwords required for company and cloud admin accounts
Screen lockWorkstations lock on inactivity; users must re-authenticate
Least privilegeProduction access limited to authorized engineering/ops/admin roles
MFAMFA enabled where available on Google / Firebase / hosting / critical admin accounts
Credential hygieneProduction secrets are not stored in source control; credentials are not shared in chat or tickets
OffboardingAccess is removed when personnel leave or change roles

4. Access control and least privilege

  • Seller TikTok Shop tokens, connection records, and order sync data are stored per user in Firebase.
  • API routes that access seller data require server-side authentication (Firebase Auth / admin verification).
  • PrepCorex uses role-based access (client, warehouse, admin/sub-admin, and feature permissions).
  • Clients can access only their own account data.
  • Admin/ops access is limited to authorized PrepCorex personnel for support and warehouse operations.
  • Secrets are stored in environment variables / secret stores, not in the client application bundle.

5. Network segregation and threat protection

LayerControl

Data platformGoogle Cloud / Firebase with project-level isolation
EnvironmentsSeparate configuration for development and production
Transport securityTLS/HTTPS for all public PrepCorex traffic
Platform protectionsCloud provider firewalling / edge protections for public services
SecretsServer-only environment variables; restricted deployment access
MonitoringProduction error monitoring and review of failed auth / integration events

6. Endpoint protection (anti-malware)

  • Company endpoints run current supported OS versions (Windows / macOS).
  • OS-native anti-malware / security is enabled (Windows Defender / macOS security features).
  • Automatic security updates remain enabled.
  • Local storage of production secrets is restricted; password managers and cloud secret configuration are preferred.

7. Data classification and encryption

ClassificationExamplesHandling
ConfidentialOAuth tokens, client secrets, refresh tokensServer-only; never logged in full; rotated/revoked on disconnect or incident
Restricted operationalSeller orders, inventory mappings, shipmentsAccount owner and authorized ops roles only
InternalSystem logs, non-secret configurationLimited to engineering/ops
PublicMarketing content, published policiesPublicly available

In transit: TLS/HTTPS for all public PrepCorex traffic.
At rest: Firebase / Google Cloud provider default encryption.
Passwords: Platform authentication hashing/encryption controls (not plaintext).

8. Vulnerability and threat management

  1. Keep application dependencies reasonably up to date
  2. Review and prioritize critical / high CVEs affecting production packages
  3. Restrict production secrets and rotate credentials when exposure is suspected
  4. Monitor production application errors and investigate security-relevant failures
  5. Apply hosting/platform security updates from Vercel and Google Cloud/Firebase
  6. Limit production deploy rights to authorized personnel

Formal penetration testing and ISO/SOC certification are not claimed in this Addendum unless separately obtained and documented.

9. Incident response

9.1 Roles

RoleResponsibility
Engineering / Ops leadTriage, containment, technical investigation
Operations / SupportSeller communication and ticket handling
ManagementEscalation, external notifications, business decisions

9.2 Process

  1. Detect — monitoring, seller report, or staff report
  2. Triage — classify severity and affected systems/data
  3. Contain — revoke tokens, rotate secrets, disable compromised access
  4. Investigate — determine scope, root cause, and data impact
  5. Remediate — patch, restore, re-enable services safely
  6. Notify — affected sellers and, when required, TikTok Shop / regulators
  7. Review — document lessons learned and improve controls

9.3 Marketplace / seller notification

If a suspected or confirmed incident may affect TikTok Shop seller data or PrepCorex integration credentials, Prep Services FBA will notify affected sellers through PrepCorex / registered email and TikTok Shop partner channels when required. Contact: privacy@prepservicesfba.com or support@prepservicesfba.com.

10. Seller / data-subject assistance

Upon verified request from a seller or TikTok Shop (as applicable), Prep Services FBA will assist to provide, update, or delete/disconnect relevant integration and account data where legally and contractually permitted. Legal/tax/audit records may be retained as required, consistent with Schedule D.

11. End of contractual relationship

  1. Marketplace connections (including TikTok Shop) are disconnected and tokens revoked/removed where feasible
  2. Seller integration credentials are deleted from PrepCorex
  3. Operational personal data is deleted or anonymized within a commercially reasonable period
  4. Legal/tax/accounting/dispute records may be retained for the required period, then deleted or archived securely

12. Third-party processors

PrepCorex uses vetted processors including Google Cloud/Firebase, Vercel, marketplace platforms (TikTok Shop, Shopify, Amazon, eBay, etc.), and configured payment/shipping providers, limited to providing PrepCorex and warehouse services.

13. Certifications

As of the effective date, Prep Services FBA LLC does not claim ISO 27001, ISO 27701, SOC 2 Type II, or ePrivacy certification unless a current certificate is separately provided.

14. Relationship to Schedule D

Schedule D remains the client-facing contractual privacy/security schedule. This Addendum provides additional operational detail for security reviewers.
